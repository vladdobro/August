Free drag: design

  
    
    
  1. Move: apply both dx and dy (drop the X pin at compact.ts:231). No clamp while moving, so the window can cross to another display; clamp on release against the display it overlaps most (screen.getDisplayMatching).
    2. 
    
  2. Release, per option: A Magnetic edges — an edge within 32 DIP of a work-area edge snaps flush with today's margin (24 caption / 16 coin), two near edges give a corner, otherwise the position stays, clamped fully inside the work area. B Free — the clamp only. C Anchor grid — always the nearest of 9 slots (3×3); for the caption only meaningful with width resize.
    3. 
    
  3. Caption height resize keeps its handle on the edge facing the display center (GhostApp.tsx:55 already derives it); main derives the fixed edge at resize start from the window center vs the work-area center instead of the last snap; max height = distance from the fixed edge to the work-area edge − 24.
    4. 
    
  4. Width resize (optional scope): 6 px handles on the left and right edges, 320–760 px, new pref compactCaptionWidth mirrored exactly like compactCaptionHeight (client default, server allow-list and clamp, caption-width event).
    5. 
    
  5. Coin hover expansion grows toward the display center from the face; if 372 px does not fit on that side it flips. The face never moves.
    6. 
    
  6. Storage (recommended): <userData>/window-state.json gets a ghost object, one record per widget: { displayId, hAnchor: 'left'|'right', hOffset, vAnchor: 'top'|'bottom', vOffset } in DIP, offset = distance from the nearest work-area edge to the window's edge. Written by main on drag end and resize end, no renderer round-trip, no server schema change. Height stays in compactCaptionHeight. Alternative (not recommended): a compactGhostPosition pref over PATCH /api/preferences like the height, which needs an object sanitizer on the server and a new compact-event only to hand the value back to main; display ids and DIP coordinates are machine geometry, like the main window bounds already in window-state.json.
    7. 
    
  7. Restore on ensureGhost: display by id, fallback the display of the main window's snapshot bounds; rect from anchors + offsets + current size; clamp into that work area; invalid or missing record → today's default (bottom center / bottom-right). While a ghost exists, screen.on('display-removed' | 'display-metrics-changed') re-clamps.
    8. 
    
  8. Off-screen recovery: every placement ends with a full clamp, so the window is always entirely inside a work area; Settings → Compact mode gets a "Reset overlay position" row (bridge method clears ghost and re-applies the default); Expand (Esc, tray click) destroys the ghost, so the user is never stuck.
    9. 
    
  9. Multi-monitor and DPI: Electron bounds and screen.getCursorScreenPoint() are DIP in one virtual screen on both platforms (left/top monitors have negative coordinates; anchors + offsets are unaffected). On Windows with mixed scale factors a transparent window can change physical size mid-drag at the DPI boundary (WM_DPICHANGED); on release re-apply the intended width/height with setBounds, not only the position. displayId keeps the record valid when the same monitor changes resolution.
    10. 
    
  10. Tools at small heights (Rodion, 2026-11-03): today the five caption tools sit in a 3-column grid, so once the height drops below what two rows of rectangles need, the second row ([ TXT ] [ ■ ]) is clipped and unreachable. The rectangles stay as long as they fit; at the point where they stop fitting the tools become one row of small squares (brackets dropped, same glyphs, hold-to-stop kept), and the minimum height / width is whatever that row needs: the window never shrinks past the point where the squares stop fitting. Both thresholds are measured from the layout, not hard-coded. Shrink the caption here to see it.
