AUG-177 — Post-100% processing indicator

After the countdown hits 00:00:00 the server still cleans up the transcript, checks the text, suggests corrections and saves. Measured on this machine: 30 s to 4 min, up to ~8 min worst case. Nothing on screen says the job is alive. Below: the current screen and three indicator variants.

The countdown is client-side only (client/src/components/TranscriptView.tsx:215 ChronoRing, :238-243): estimatedDuration × elapsed time. estimatedDuration = audio seconds × median ratio of the last 10 runs (server/src/services/performanceTracker.ts getEstimatedRatio). The ratio measures start → completed, so it includes the semantic pass, which is not proportional to audio length and depends on settings; recorded ratios on this machine range 0.019–0.38. Real cases: 255 s call → ring at zero after 34 s, work done at 69 s; 370 s call → zero at 33 s, done at ~62 s. SessionStatus (server/src/types.ts:3) has no post-processing stage.

Rules for the stage label:

  • User words only (no method names, no timings, no model names — project rule «no diagnostics in user UI»).
  • Label changes at most every poll.
  • Unknown stage falls back to "Finishing".
