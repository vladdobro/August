Send to Praxis — remember picked projects

AUG-171 · Rodion's Bug Fix 2: a project picked by folder is not kept, so the path is re-entered every time. Pick an option below.

Show

Current flow

  • PraxisModal.tsx:80,102-126 — on open the modal reads the last path from localStorage['august-praxis-project-path']; a match selects that chip, otherwise fills "Other…" + path.
  • PraxisModal.tsx:186-199 — the path is written to localStorage only after a successful send.
  • PraxisModal.tsx:142-155 — "Open" (folder picker, POST /api/praxis/browse) only fills the path field; it never registers a project.
  • electron/src/main.ts:195,610 — the packaged app starts the server on port 0, so the page origin http://127.0.0.1:<port> changes every launch and localStorage starts empty. root cause
  • praxisProjects preference (path, name, isDefault, prompt) is the only registered list; edited on Settings → Projects; sanitizePraxisProjects dedupes by resolved path, case-insensitive.

Options

Dialogs below are live mocks: click chips, ×, Save and Undo. Sample projects: August (default) and squarefi-crm; picked folder: D:\Проекты\Rodion-notes.

A — Remember the last path

Store the last sent path in server preferences (praxisLastPath) instead of localStorage, so it survives restarts.

Pros

  • Fixes the root cause
  • Zero list growth
  • Tiny change (one pref key + modal init)

Cons

  • Only one path; switching between two unregistered folders still needs re-picking
  • Not visible in the Project list (Rodion asked for that)

B — Auto-add to Projects with [x]

After a successful send, an unregistered path is appended to praxisProjects (named after the folder).

Pros

  • Exactly what Rodion asked
  • One list everywhere (Settings → Projects shows it too)

Cons

  • Wrong-but-valid picks pollute the registered list (Vlad's "15 projects" concern)
  • Past 5 projects the chips turn into a dropdown, so [x] also has to live in dropdown rows
  • × next to a chip is an easy misclick (needs Undo)

C — Recent picks, capped at 3 recommended

Successful sends to unregistered paths go into a separate praxisRecentPaths list (max 3, newest first, server preference). Registered Projects stay curated; recents expire on their own.

Pros

  • One-click reuse of picked folders
  • Junk self-limits (cap 3) plus ×
  • Settings → Projects stays clean; "Save" promotes a keeper

Cons

  • Two kinds of chips to explain
  • A bit more code than A (new pref key + sanitizer + UI)

Recommendation

C — Recent picks, capped at 3. It keeps Rodion's one-click reuse, answers Vlad's junk concern without discipline (the list cannot grow past 3), and keeps registered Projects curated. A is a subset of C: C also restores the last path after restart.

Shared rules for any option
  • Only add a path after the task is created (a validated .praxis/ folder) — failed sends never get remembered.
  • Store in server preferences, not localStorage (origin port changes per launch).
  • Dedupe by resolved path, case-insensitively (same as sanitizePraxisProjects).
  • Store the path exactly as entered/picked — never the 8.3 short form. Non-ASCII paths (Cyrillic) must round-trip on Windows and macOS.
  • A path that later loses its .praxis/ folder stays listed and fails with the existing validation error.
