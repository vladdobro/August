AUG-172 · Resizable Default Prompt

Feedback (Rodion): the Default Prompt field in Settings → Projects is too small to read the whole prompt.

Current state
  • Default editor textarea PraxisProjectsPage.tsx:407 sits directly in .praxis-md-detail, not in .praxis-md-field--grow → no flex:1, no min-height → browser default 2 rows (~44px).
  • .praxis-md-textarea { resize: none } (App.css:7458) overrides .settings-textarea { resize: vertical } (App.css:7367) → cannot drag.
  • Per-project prompt textarea (PraxisProjectsPage.tsx:523) is in --grow (App.css:7456-7457, flex:1, min-height 120px) → fills the pane, but also not resizable.
  • Settings card 600px wide, Projects tab 85vh tall (App.css:6975, 7429); list column 210px → editor pane ≈390px wide.

Current Bug

Reproduces the report: the Default editor renders as a 2-row field and cannot be resized.

Pros / cons: n/a (this is the bug).

A · Drag handle

Explicit-height textarea with a 6px handle under it that the user drags (or moves with arrow keys).

height persisted: yes

Pros

  • Familiar interaction, same pattern as the Ghost Caption resize handle
  • User controls the size
  • Persisted between sessions

Cons

  • Pane is capped at 85vh anyway, so the drag range is small (~120 to ~380px)
  • Extra state to persist (new preference or localStorage)
  • Needs keyboard support to be accessible
  • Still can't see a 48-line prompt at once

Implementation sketch: wrap the textarea in a fixed-height div, add a role="separator" handle with pointer capture, clamp 120px to available pane height, store height under one key. Double-click resets to 160px.

B · Fill + auto-grow

Wrap the Default textarea in .praxis-md-field--grow like the per-project editor, so it takes all remaining pane height.

showing ~0 of 0 lines

Pros

  • One CSS/JSX fix
  • Matches the per-project editor and the documented intent ("full-height textarea")
  • No persistence, zero new UI

Cons

  • Max height bounded by the 85vh modal
  • Very long prompts still scroll

Implementation sketch: in PraxisProjectsPage.tsx wrap the Default textarea in <div className="praxis-md-field praxis-md-field--grow">; no new CSS beyond what --grow already provides.

C · Fill + Expand

Same as B, plus an EXPAND button that opens a full-window editor for long prompts.

Try the EXPAND button, or press Ctrl/Cmd+Shift+E with the textarea focused. Esc or DONE closes.

Pros

  • Sees the whole prompt on big screens
  • Works for per-project prompts too
  • No persistence

Cons

  • One more component (overlay)
  • Focus/Esc handling must not close the Settings modal underneath (stopPropagation)
  • Extra click

Implementation sketch: B, plus a PromptExpandOverlay (portal, fixed inset, blur backdrop) taking value/onChange; open from a button in the chips row, focus the textarea on open, return focus on close.

Recommendation

B + C. B is the actual fix: the Default editor lost the grow wrapper the per-project editor has, so it renders 2 rows. C adds a one-click full-window editor for long prompts, in both Default and per-project editors. A (drag handle) is not recommended: the pane is already capped by the 85vh modal, so dragging buys little and needs a persisted height.
